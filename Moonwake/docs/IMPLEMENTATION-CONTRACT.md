# Moonwake implementation contract

Native Swift 5, iOS 26+, SpriteKit gameplay with SwiftUI Liquid Glass overlays. Landscape iPhone. No dependencies or runtime network requests. Reference: white-haired red-scarfed hero, cyan glowing greatsword, amber spirit, mossy golden little guardian, horned boar and flying hornet, lush coastal moonlit pixel art. Do not embed reference ad or its text/logo.

## Ownership
Root: GameTypes.swift, GameStore.swift, GameServices.swift, app entry, project/build/test/release.
Art agent: PixelArt.swift, WorldBuilder.swift and native generated app icon.
Gameplay agent: GameScene.swift (plus helper source files if useful).
Interface agent: GameViews.swift (plus helper SwiftUI view files).

## Art API
`PixelArt.texture(_ name: String, frame: Int = 0) -> SKTexture` nearest filtering, caching. Names hero, moss, wisp, slime, boar, hornet, wraith, knight, boss0 through boss4, sword, tree, bush, flower, grass, rock, crystal, rune, beacon, chest, portal, keeper, ruin. Design sprites at 16–48 px; gameplay scales to roughly 40–70 point character sizes. Add `PixelArt.sprite(_ name: String, frame: Int = 0, scale: CGFloat = 2) -> SKSpriteNode` if useful. `WorldBuilder.build(realm: Realm, completed: Bool) -> WorldMap` with render root, fixed world coordinates, accessible navigation and 3 runes, beacon, boss, NPC, portal and 2 chests. World should be 1800–2200 × 1300–1600 points. All major points reachable; keep obstacles away from interaction positions and connecting paths. Decor baked per world where possible, animated selective water/firefly overlays. Layering use z positions with world objects sorted by negative y /100. Root ground z=-1000; player objects near 0. Do not add gameplay interactable sprites (runes/beacon/chest/portal/NPC) into world root: scene creates those for state updates. World builder may add decorative ruins and ring bases.

## GameScene API
`@MainActor final class GameScene: SKScene` has `init(store: GameStore)`, `begin(realm: Realm)`, `showTitleScene()`, `syncSettings()`, `captureForQA(name: String)` optional. Scene reads `store.mode`; gameplay runs only .playing. Store weak scene reference assigned by root. Title scene is atmospheric frozen world with ambient animations. Save progress tracks rune ids `realm-index`, chest ids same. Rune activates by interact within ~90. Boss enabled when 3 runes activated; guarded beacon can be restored only boss dead + runes. Restored beacon unlocks next realm; portal interacts to `store.travel(to:)`. Final restoration calls `store.completeGame()`. Each region should have a distinct guardian, telegraphs, enemy attacks, sword combos, dash invulnerability, pulses, health pickups, floating damage, hit feedback and animated hero companions. `GameInput` flags are one-shot, clear after processing. Movement is CGVector normalized (-1...1). All movement and collision must use WorldMap.canWalk. Passable worlds have fixed points. No damage during overlays. Scene updates store health/energy/stamina and contextual hint as needed, throttles UI updates. Dead player calls store.defeat().

## GameStore API (root implementing)
ObservableObject @MainActor. Published: `mode: GameMode`, `progress: GameProgress`, `settings: GameSettings`, `health: Double`, `energy: Double`, `stamina: Double` (0..100), `bossName: String`, `bossFraction: Double` (0 hides), `hint: String`, `toast: String?`, `dialogue: Dialogue?`, `banner: String?`, `hasSave: Bool`, `saveWarning: String?`. `let input = GameInput()`, `weak var scene: GameScene?`, `let services = GameServices()`.
Methods: newGame(), continueGame(), resume(), open(GameMode), returnToTitle(), retry(), travel(to: Realm), purchase(Upgrade), save(), notify(String), speak(String, lines: [String]), advanceDialogue(), defeat(), completeGame(), restoreVitals(), activateRune(index: Int, realm: Realm), defeatBoss(in: Realm), lightBeacon(in: Realm), claimChest(index:Int, realm:Realm), addEssence(Int), usePotion(), updateSettings(), resetSettings(), attack(), dash(), pulse(), interact(), heal(). `lightBeacon` updates progress and ending automatically. Model functions mutating progress as needed may be used but call save after important milestones. Services functions `play(_ cue: SoundCue)`, `haptic(_ kind: FeedbackKind)`, `update(settings: GameSettings)`, `startMusic()`, `stopMusic()`; enums SoundCue: sword, hit, dash, pulse, rune, reward, hurt, defeat, victory, menu, step; FeedbackKind: light, medium, heavy, success, warning.

## SwiftUI
Root `GameRootView(store: GameStore, scene: GameScene)` composes SpriteView and overlays. Store comes from app @StateObject. Use native .glassEffect and GlassEffectContainer with iOS26 minimum. Main title needs strong typographic identity, subtitle, Continue when saved, Begin journey, Journal/Settings. Real HUD health/energy, objective based on runes/boss/beacon, map/journal button. Joystick input, attack/dash/pulse/interact/heal, correct safe area and multitouch. Menu/settings/journal/upgrades/defeated/ending/dialogue complete and functional. Settings controls persist via store.updateSettings; no placeholder buttons. Upgrades all capped at4. UI accessibility identifiers title.begin, title.continue, game.pause, game.attack, game.dash, game.pulse, game.interact, game.heal, pause.resume, pause.journal, pause.upgrades, pause.settings, pause.title, menu.back, journal.realm.N, ending.title. Support Reduce Motion/Transparency. Title/menus can scroll at large Dynamic Type. Do not intercept entire SpriteView with a blocking touch layer. SwiftUI drawing can be native vectors for HUD, all game visuals SpriteKit.
